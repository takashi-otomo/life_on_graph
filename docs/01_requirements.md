# 01. 要件定義 — Life On Graph (LOG)

## 1. 背景・目的

Android ヘルスコネクトには、各種ウェアラブル (Wear OS / Galaxy Watch / Fitbit / Garmin 等) や
アプリが記録した生体データが集約される。本アプリ **Life On Graph (LOG)** は、ヘルスコネクトに
蓄積された **睡眠・歩数・脈拍 (心拍)** データを取得し、ユーザーが自身の健康状態を直感的に
把握できるよう可視化することを目的とする。

データはクラウドに送信せず端末内で完結させ、プライバシーを最優先する。

## 2. スコープ

### 2.1 対象に含む (初期スコープ)
- Android ヘルスコネクトからのデータ取得 (睡眠・歩数・心拍)
- ローカル DB (Hive / AES-256 暗号化) への永続化
- 起動時 / 手動操作によるフォアグラウンド差分同期 (インクリメンタル同期)
- データクレンジング (重複解消・境界クリッピング・隣接結合)
- 3 種データの可視化 (睡眠ステージグラフ・歩数グラフ・心拍グラフ)
- 睡眠時間帯と心拍・歩数の時間軸マッピング表示

### 2.2 対象に含まない (将来 / 別フェーズ)
- iOS (HealthKit) 対応 — ※ `health` パッケージ採用により拡張余地は残す
- クラウドバックエンドへのデータ送信・同期
- WorkManager によるバックグラウンド定期同期
- データ書き込み (本アプリは読み取り専用を基本とする)
- 体重・血糖値・呼吸数など睡眠/歩数/心拍以外のデータ種別

## 3. 対象プラットフォーム / 動作要件

| 項目 | 内容 |
| --- | --- |
| OS | Android 9.0 (API 28) 以上 |
| minSdkVersion | 26 |
| compileSdkVersion | 34 |
| ヘルスコネクト | API 34 以上はネイティブ統合 / API 33 以下は Play からの手動インストールが必要 |

## 4. 機能要件

### FR-1: パーミッション管理
- 起動時にヘルスコネクトの導入有無を検出する (未導入時は導入導線を提示)。
- 睡眠 (READ_SLEEP)・歩数 (READ_STEPS)・心拍 (READ_HEART_RATE) の読み取り権限を申請する。
- 申請権限は上記 3 種に**限定**する (データ最小化原則)。
- 初回バックフィルのため履歴データ権限 (READ_HEALTH_DATA_HISTORY) を申請する。許可されない場合は過去 30 日にフォールバックする。

### FR-2: データ取得 / 同期
- 初回同期: 過去 30 日 (履歴権限があればそれ以前も可) をバックフィルする。
- 差分同期: 前回同期完了時刻 (`last_sync_time`) から現在までの新規・更新データのみ取得する。
- 取得データはヘルスコネクトの `uuid` をキーに Hive へ保存し、重複を排除する。
- 差分が極小 (例: 5 分未満) の場合はクエリをスキップしリソースを保護する。

### FR-3: データクレンジング
- データソース優先順位 (`dataOrigin` / `sourcePackage`) に基づき信頼ソースを優先する。
- 表示対象日 (例: 正午〜翌正午の 24 時間枠) に境界クリッピングする。
- 同一時間帯の重複オーバーラップを解消する (長いセグメント優先)。
- 短間隔 (例: 30 秒未満) の同一ステージを結合する。

### FR-4: 睡眠可視化
- 睡眠ステージ (DEEP / LIGHT / REM / AWAKE / OUT_OF_BED / AWAKE_IN_BED / UNKNOWN) を積層タイムラインで表示する。
- 1 日単位でセッションを表示し、合計睡眠時間・各ステージ比率を集計表示する。

### FR-5: 歩数可視化
- 日次 / 時間帯別の歩数を棒グラフ等で表示する。
- 期間集計 (日 / 週) を切り替え可能にする。

### FR-6: 脈拍 (心拍) 可視化
- 時系列の心拍数を折れ線グラフで表示する。
- 睡眠セッションの開始〜終了でフィルタした「睡眠中心拍」を表示できる。

### FR-7: クロスデータ統合表示
- 睡眠セッションの時間境界 (t_start ≤ t ≤ t_end) で心拍・歩数を時間軸マッピングし、
  睡眠の質との相関を 1 画面で俯瞰できるようにする。

### FR-8: ローカルファースト UX
- 起動時はローカル DB から即時描画し、読み込み待ち (ブロッキング) を発生させない。
- 同期完了後にリアクティブに UI を更新する。
- オフラインでも過去データを閲覧できる。

## 5. 非機能要件

| ID | 区分 | 要件 |
| --- | --- | --- |
| NFR-1 | セキュリティ | ローカル DB を AES-256 で暗号化。鍵は `flutter_secure_storage` で隔離保存 |
| NFR-2 | プライバシー | ヘルスデータを外部送信・平文ログ出力しない。データ最小化を徹底 |
| NFR-3 | パフォーマンス | 起動から初期描画まで待ちが発生しない (ローカルファースト) |
| NFR-4 | 省電力 | 不要な再クエリを避け、差分同期でバッテリー消費を抑制 |
| NFR-5 | 互換性 | Android 9.0 以上 / ヘルスコネクト導入有無を判定しフォールバック |
| NFR-6 | 保守性 | レイヤ分離 (Presentation / Repository / DataSource) と TDD |
| NFR-7 | コンプライアンス | Google Play ヘルス申告・プライバシーポリシー・CASA 要件に準拠 |

## 6. 制約・前提

- ヘルスコネクトにはサーバー API が存在せず、すべてローカルで完結する。
- 睡眠・心拍・歩数はリレーションシップ ID を持たず、時間境界で関連付ける必要がある。
- 複数ソースが同一時間帯に書き込むデータ衝突が日常的に発生する前提でクレンジングする。
- デフォルトでは権限付与時点から最大 30 日の履歴しか読み取れない。

## 7. 用語

| 用語 | 説明 |
| --- | --- |
| ヘルスコネクト | Android のオンデバイス健康データハブ |
| ローカルファースト | ローカル DB を一次ソースとし即時描画する設計 |
| インクリメンタル同期 | 前回同期以降の差分のみを取得する同期方式 |
| クレンジング | 重複・はみ出し・隣接データを整形する前処理 |
| CASA | Cloud Application Security Assessment (クラウドアプリセキュリティ評価) |
