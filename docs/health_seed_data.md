# Health Connect テストデータ シーダー

エミュレータ/実機の Health Connect に、過去 2 か月分(60 日)の **睡眠・歩数・心拍**
ダミーデータを投入するデバッグ専用ツール。UI(可視化・サマリー)とクレンジング
ロジックの **エッジケース** を実機環境で網羅的に検証するために用いる。

- ツール本体: [`tool/health_seeder.dart`](../tool/health_seeder.dart)
- WRITE 権限: `android/app/src/debug/AndroidManifest.xml`(**デバッグビルド専用**)

> ⚠️ 製品(release)アプリは Health Connect の **READ 権限のみ**を申請する(データ最小化)。
> WRITE 権限とシーダーはデバッグビルドにのみ存在し、出荷物には含めない。

## 実行手順

```bash
# 1) エミュレータ/実機を起動
flutter emulators --launch <avd-id>          # 例: Medium_Phone_API_36.1

# 2) シーダーを起動 (デバッグビルド = WRITE 権限が有効)
flutter run -t tool/health_seeder.dart -d <serial>

# 3) 画面の「過去2か月分のテストデータを投入する」をタップ
#    → Health Connect の WRITE 権限ダイアログで「許可」
#    → 投入完了まで待つ(数千件のため数十秒)

# 4) LOG アプリを起動し、日付ナビで各日へ移動して確認
scripts/run_app.sh <serial>
```

## 日付と表示の対応

- **睡眠**: 「k 日前」の夜(その日の 23:00 起点)に投入する。LOG は正午〜翌正午を 1 日の
  表示枠とするため、**LOG で「k 日前」の日付を選ぶ**とその夜の睡眠が表示される。
- **歩数 / 心拍**: 暦日(k 日前の 0:00〜24:00)に投入する。LOG で同じ日付を選ぶと表示される。

## シナリオ一覧(エッジケース)

各日(k 日前)に以下のシナリオを割り当てている。番号は `tool/health_seeder.dart` の
`_SeedGenerator.generate()` と一致する。

| k 日前 | シナリオ | 投入目的(検証観点) |
| --- | --- | --- |
| 1 | 標準的な夜 + 活動的な日 | 全ステージ・日跨ぎ睡眠 / 通常歩数 / 通常心拍の基本表示 |
| 2 | 短時間睡眠(約3時間) | 睡眠合計が短い場合のサマリー・タイムライン |
| 3 | 長時間睡眠(約10時間) | 睡眠合計が長い場合の比率バー・合計表示 |
| 4 | 睡眠なし(歩数/心拍あり) | 睡眠カードの **空状態** + 他データは表示される |
| 5 | 昼寝のみ(日中睡眠) | 夜以外の睡眠セッションのタイムライン表示 |
| 6 | 分断睡眠(微小覚醒多数) | 隣接結合(`mergeAdjacentSameStage`)・覚醒過多の表示 |
| 7 | 歩数ゼロ日 | 歩数カードの **空 / ゼロ表示** |
| 8 | 高歩数日(約25000) | 棒グラフの最大値スケーリング |
| 9 | 歩数が日跨ぎ | 区間が午前0時をまたぐ歩数の **按分集計**(P1-2 検証) |
| 10 | 運動による高心拍スパイク(180) | 心拍折れ線の上振れ・最高値表示 |
| 11 | 安静時心拍が非常に低い(40) | 心拍の下振れ・安静値表示 |
| 12 | 心拍データなし | 心拍カードの **空状態** |
| 13 | 浅い睡眠のみ(deep/rem なし) | 一部ステージ欠如時の比率バー・凡例 |
| 14 | 覚醒過多の夜 | 覚醒比率が高い場合の表示 |
| 15 | out_of_bed / awake_in_bed ステージ | 覚醒エイリアスの **正規化**(awake へ畳み込み) |
| 16 | 睡眠セグメント重複(同一ソース) | オーバーラップ解消(`mergeOverlaps`)の検証 |
| 17 | 正午境界をまたぐ昼寝(11:30→12:30) | 境界クリッピング(`clipSegmentsToDay`)の検証 |
| 18 | 不明(unknown)ステージ含む | unknown ステージの集計・凡例表示 |
| 19 | 心拍が疎(1日数点) | 心拍データが少ない場合の折れ線 |
| 20 | 心拍が密(5分毎) | 心拍データが多い場合の折れ線描画性能 |
| 21〜60 | ベースライン | 通常範囲の睡眠/歩数/心拍。時系列の連続性・サマリーの平均/トレンド |

## 制約・既知事項

- **クリーンな Health Connect ストアで投入すること**: シーダーは信頼リスト外の単一ソース
  (`dev.otomo.life_on_graph`)として書き込む。**実機に Samsung Health / Fitbit 等の信頼ソースの
  同日睡眠が既に存在する**と、`allocateBySourcePriority` は信頼ソースが在る場合に信頼外を除外
  するため、シードした睡眠が表示されず実データ側が優先される。テスト用エミュレータなど
  クリーンなストアで投入すること(クリーン時はフェイルオープンでシードが表示される)。
  なお複数ソース衝突時の優先順位選別自体は
  [`test/unit/cleansing_test.dart`](../test/unit/cleansing_test.dart) で検証済み。
- **再投入時は LOG のローカルデータも消去推奨**: シーダーは安定した `clientRecordId` で
  書き込むため Health Connect 側は冪等(上書き)。HC 側で削除したレコードは次回同期で
  LOG からも除去される([#64](https://github.com/takashi-otomo/life_on_graph/issues/64) 実装済み)。
  ただし投入内容を作り変える(時刻やキーが変わる)場合は古いレコードが残り混在しうるため、
  クリーンに作り直すには LOG のアプリデータを消去してから初回バックフィルするのが確実:
  `adb shell pm clear dev.otomo.life_on_graph`(または設定→ストレージ→消去)。
- **過去2か月の全件取得には履歴権限が必要**: LOG の初回バックフィルは履歴権限なしだと
  過去30日に制限される。LOG 起動時の権限ダイアログで「過去データへのアクセス」も許可すると
  365日まで遡って 60 日分すべてを取得できる。
- **投入の部分失敗**: 書き込みクォータが回復しきらないと一部が失敗しうる。その場合シーダーは
  「⚠ 一部失敗」と件数を表示する。再実行すると `clientRecordId` により冪等に補完される。
